# VendSolution 多智能体选品引擎 · 架构与方法论

> 本产品**不是**边缘端 / 本地柜内模型。选品决策由云端「多智能体协同分析 + CEO 综合决策」完成。
> 核心思路：多个专家智能体分别从各自维度研判，再由一个 CEO 智能体综合所有人的报告，输出最终可落地的选品与补货清单。

---

## 1. 总体架构（两层）

```
            ┌─────────────────────────────────────────────┐
  场景数据   │           多智能体层（分析层 / Tier 1）          │
 （柜机·位置 │                                            │
  ·天气·节 │  ① 运营智能体      ② 历史销售智能体          │
  假日·社 │  ③ 维度智能体群（天气/节假日/周边/CRM/趋势/商品库）│
  媒·商品库）│                                            │
            └───────────────────┬────────────────────────┘
                                │ 各自输出一份结构化分析报告
                                ▼
            ┌─────────────────────────────────────────────┐
            │           CEO 决策层（综合层 / Tier 2）         │
            │  读取全部报告 → 权衡利润/缺货/浪费 → 输出：    │
            │  · 最终 Top N 选品清单                        │
            │  · 每个 SKU 的补货量 / 优先级                │
            │  · 增补 / 试销 / 维持 / 清减 分类与理由      │
            └─────────────────────────────────────────────┘
```

**为什么不是"本地模型"？**
选品依赖跨设备历史、实时天气、社媒趋势、周边业态等**外部与全局信号**，这些无法、也不应塞进单台柜机的芯片里。真正的价值在"多源信息 + 综合研判"，而非"跑在哪里"。

---

## 2. 多智能体层（Tier 1：分析）

每个智能体只看自己擅长的一块，互不干扰、各自产出一份报告。这样既避免单一模型"什么都答一点、什么都不深"，也让每个结论都能**追溯到是哪位专家、哪条证据**。

### ① 运营智能体（Operations）
掌握柜机的**运营约束**，确保建议"能落地"：
- 补货时间窗（如写字楼早 7:45 前必须满仓，否则错过早高峰）
- 货道容量 / 陈列规则
- 毛利结构与定价空间
- 临期、损耗、融化等品质风险

### ② 历史销售智能体（Historical Sales）
回答"过去到底卖得怎么样"：
- 同类设备历史销量与相关性
- 双高峰 / 单峰 流速曲线（早高峰咖啡因、午间代餐…）
- SKU 周转速度、连带购买、滞销识别

### ③ 维度智能体群（Dimensions）
按场景加载多个外部维度，把"当下环境"量化进决策：
| 维度 | 作用 |
|---|---|
| 天气 | 温度/湿度/降水 → 冷饮、热饮、补水系数 |
| 节假日 / 寒暑假 | 客流峰值与结构变化 |
| 位置与周边业态 | 写字楼 / 乐园 / 地铁 / 健身房… |
| 顾客反馈（CRM / 会员评价） | 缺货投诉、口味诉求、复购信号 |
| 社媒趋势 | 小红书 / 本地生活热度、IP 联名、新品 |
| 商品知识库（自有 retail 数据源） | 真实在售 SKU、反馈次数、畅销榜 |

> 在**真实链路**中，这些智能体由 InfiniSynapse 驱动（默认 deepseek-v4-flash），每次分析都会在 InfiniSynapse 后台留下**可查任务日志**——这是比赛对"真实后端调用"的硬性要求。

---

## 3. CEO 决策层（Tier 2：综合）

CEO 智能体读取全部专家报告，按统一目标做权衡：
- **目标**：利润最大化、缺货最小化、浪费最小化
- **动作**：
  - 将候选 SKU 分为 **增补 / 试销 / 维持 / 清减** 四类
  - 给出每个 SKU 的**补货量**与**优先级**
  - 输出一份**人类可读的最终选品清单 + 理由**

> 乐高乐园场景的 CEO 由 Favor 平台的 **qwen3-max** 担任；CBD 深圳南山场景的 CEO 由 Favor 平台的 **ChatGPT（gpt-5.5）** 担任。两条链路共用同一套多智能体分析层。

---

## 4. 一个完整例子（CBD · 深圳南山区科兴科学园）

| 角色 | 输入 / 发现 | 结论贡献 |
|---|---|---|
| 运营智能体 | 早 7:45 前须满仓，否则失峰；巧克力棒临期 7 天 | 冷萃必须满仓；巧克力棒降价清仓 |
| 历史销售智能体 | 冷萃 + 无糖补水占营收 64%；巧克力棒日均周转 0.1 | 主推饮品，砍死库存 |
| 维度·天气 | 明日 35°C，紫外线极强 | 冰饮 ×1.8 补货系数 |
| 维度·周边 | 200m 内新开 2 家高端健身房 | 天然等渗 / 代餐需求上行 |
| 维度·CRM | 14 条冷萃缺货反馈 + 9 条午间代餐诉求 | 增补冷萃、试销高蛋白代餐奶昔 |
| **CEO（gpt-5.5）** | 综合上述 | Top 8：无糖茶 / 三得利乌龙 / 外星人电解质水 / 宝矿力 / 无糖冷萃 / 雀巢冰美式 / IF 椰子水 / 元气森林 0 糖气泡水；清减巧克力棒 |

---

## 5. 这样设计的好处

1. **分而治之**：每个智能体聚焦单一维度，分析更深、更稳定。
2. **可解释**：任何一条选品建议都能回溯到"哪个智能体 + 哪条证据"，不是黑箱。
3. **可核查**：真实链路每次调用都在后台留存任务日志，满足比赛"真实后端"要求。
4. **可复制**：换场景只需替换维度智能体的数据源与文案（乐高 / CBD 已验证，鸟巢为演示用模拟数据）。
